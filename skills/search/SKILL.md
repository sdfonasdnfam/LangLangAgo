description: 搜索网页并核对来源，覆盖问题后及时整理
keywords: [搜索, 查找, 查询, search, find]
---
1. 提炼搜索关键词和用户需要的主题。默认每个主题找到 1–2 个直接相关的可靠页面即可，不做全站研究。
2. 已知官网入口时直接打开；需要搜索引擎时直接导航到带 URL 编码关键词的搜索 URL，省去输入框交互。
3. 先从当前页面的相关链接定位候选；只有找不到候选时才查看文档索引。读过一份适用索引后，先核对候选正文，不再枚举其他语言、父级索引或 sitemap。不要要求页面标题恰好等于用户术语，内容覆盖即可。
4. 优先使用 browser_read_page 一次打开并读取页面标题、正文和链接，减少模型往返。导航只返回页面结构文件路径时，用 browser_evaluate 一次提取 main/article 的标题、相关段落和链接；不要用 document.body 的前几段导航菜单代替正文。仅在需要元素 ref 交互时读取页面结构。
5. 优先核对最相关的 2–4 个页面。互不依赖的只读读取可以合并在一次 browser_run_code 中，返回各页 URL、标题、相关段落，不返回完整网页。
6. 每次得到结果后检查是否覆盖用户的全部主题。覆盖后立即输出“主题 / 页面标题和链接 / 涵盖内容”，不要继续扩展教程、案例或寻找唯一的专门页面。
7. 临近预算上限时用已有证据作答。区分已读正文和仅见索引的页面；不足则说明，不编造结果。
